# PTA Green Tech Daily：客户从零使用 Codex 操作指南

这份指南适合第一次使用 Codex 的运营人员。目标是让 Codex 自动完成：

> 搜索绿色技术新闻 → 核验和去重 → AI 自动评分 → 生成贴图 → 放入公众号贴图草稿箱 → 按需自动提交发布

项目已经区分两套流程：

- 周一：只汇总刚过去的周六、周日；
- 周二至周五：搜索运行时间前 72 小时的新闻；
- 周六、周日：默认不运行。

## 1. 打开 Codex，让它下载项目

在电脑上安装并登录 Codex 桌面版，然后新建一个任务。复制下面这段话发给 Codex：

```text
请把下面这个 GitHub 项目的 codex/green-daily-skills 分支克隆到我的电脑，并打开其中的 green-daily 项目：
https://github.com/AD0901/wechat-article-publisher-skill.git

克隆后请检查项目结构，但暂时不要创建公众号草稿，也不要自动发布。
```

Codex 如果弹出下载、联网或运行命令的授权提示，确认目标是上述 GitHub 仓库后，再点击允许。

完成标志：Codex 能找到下面两个文件。

```text
green-daily/skills/weekday-green-tech-daily/SKILL.md
green-daily/skills/monday-green-tech-weekend-roundup/SKILL.md
```

## 2. 让 Codex 完成初始化

在刚才的任务里继续发送：

```text
请为这个项目完成首次初始化：
1. 安装项目所需依赖；
2. 检查周一和周二至周五两个 Skill 是否完整；
3. 检查新闻搜索、图片生成和公众号贴图草稿所需能力；
4. 不要使用演示新闻代替真实新闻；
5. 暂时不要创建草稿或公开发布。

完成后只告诉我：哪些检查通过、哪些还需要我配置。
```

如果 Codex 建议安装这两个 Skill，可以允许安装。即使没有安装，也可以直接让 Codex按两个 `SKILL.md` 文件执行。

## 3. 安全配置公众号，并做第一次贴图草稿测试

### 3.1 客户需要准备

- 公众号 AppID；
- 重新生成的 AppSecret；
- 公众号后台已开放的草稿、素材及发布接口权限；
- 将运行这套任务的电脑或服务器出口 IP 加入公众号 IP 白名单。

不要把 AppSecret 发在普通聊天、截图、邮件或 GitHub 中。

让 Codex先创建本地配置模板：

```text
请在 green-daily 目录中，根据 .env.example 创建一个本地 .env 文件。
这个文件必须被 Git 忽略，绝对不能提交到 GitHub。
请只保留待填写位置，不要让我把 AppSecret 发在聊天里。
```

然后由客户本人在电脑上打开 `green-daily/.env`，填写：

```text
WECHAT_APPID=客户公众号的AppID
WECHAT_APPSECRET=客户公众号的新AppSecret
WECHAT_PUBLISH_MODE=draft_only
```

第一次测试必须保持 `draft_only`。配置好后对 Codex 说：

```text
请完整读取并执行 green-daily/skills/weekday-green-tech-daily/SKILL.md，
做一次真实新闻试跑。我确认本次可以创建公众号“贴图”草稿，
但禁止公开发布，禁止群发。

请核验新闻时间、原文网址、中外来源、十大领域扫描情况和图片差异。
完成后告诉我贴图草稿 media_id，以及是否确实为 newspic 类型。
```

完成后，客户进入公众号后台的“草稿箱”，确认内容位于“贴图”，不是“文章”。

只有下面内容全部正确，才能继续下一步：

- 首图是当天封面；
- 后续图片与各条新闻一一对应；
- 图片下方有新闻文字、原文网址和活动信息；
- 没有重复新闻；
- 没有测试数据或无法核验的数据。

## 4. 创建周一和周二至周五两条定时任务

先决定运行模式：

- 稳妥模式：保留 `WECHAT_PUBLISH_MODE=draft_only`，每天只生成贴图草稿，由人发布；
- 无人值守模式：将 `.env` 改为 `WECHAT_PUBLISH_MODE=auto_submit`，系统会自动提交微信发布审核。

注意：`auto_submit` 不会绕过微信平台审核，也不等于群发给全部粉丝。即使任务在 08:00 提交，实际可见时间仍取决于微信审核。

### 4.1 创建周一任务

在 Codex 中发送：

```text
请为当前 green-daily 项目创建一条本地定时任务：

名称：周一绿色技术周末汇总
时间：每周一，北京时间 08:00
要求：完整读取并执行
green-daily/skills/monday-green-tech-weekend-roundup/SKILL.md。
只收集刚过去周六、周日的新闻，扫描十大领域，核验中外来源，
与历史内容去重，生成公众号 newspic 贴图。
任何硬性校验失败时停止创建或提交，不得用低质量新闻凑数。
发布方式严格读取本地 .env 中的 WECHAT_PUBLISH_MODE。
```

### 4.2 创建周二至周五任务

继续发送：

```text
请为当前 green-daily 项目再创建一条本地定时任务：

名称：周二至周五绿色技术日报
时间：每周二、周三、周四、周五，北京时间 08:00
要求：完整读取并执行
green-daily/skills/weekday-green-tech-daily/SKILL.md。
只使用运行时间前 72 小时内可核验的真实新闻，扫描十大领域，
至少包含中国和国际动态，与周一汇总及历史内容去重，
生成公众号 newspic 贴图。
任何硬性校验失败时停止创建或提交，不得用低质量新闻凑数。
发布方式严格读取本地 .env 中的 WECHAT_PUBLISH_MODE。
```

创建后进入 Codex 左侧的“已安排”，确认：

- 周一任务只勾选周一；
- 工作日任务只勾选周二、周三、周四、周五；
- 两条任务都绑定正确的 `green-daily` 项目；
- 时区为北京时间；
- 任务处于“已开启”状态。

## 5. 日常查看、临时运行和故障处理

### 手机查看

定时任务实际运行在客户电脑上的 Codex 中，任务结果应以电脑端“已安排”和对应任务记录为准。同一账号能否在手机端同步看到通知，取决于客户当前使用的 ChatGPT/Codex 客户端能力，不能把手机消息当作唯一的运行凭证。公众号贴图草稿仍需要在公众号后台或相应的公众号管理工具中查看。

### 临时手动运行

需要立即补跑时，在项目任务里发送：

```text
请按今天是星期几，自动选择正确的绿色技术日报 Skill 立即运行一次。
严格去重，并按照本地 .env 的发布方式执行。
```

### 临时停止自动发布

把 `.env` 中这一行改回：

```text
WECHAT_PUBLISH_MODE=draft_only
```

这样定时任务仍会生成贴图草稿，但不会自动提交公开发布。

### 电脑运行条件

这是本地定时任务。到点时需要保证：

- 电脑开机且未长时间休眠；
- 网络可用；
- Codex 可以访问项目；
- 外网新闻源和微信 API 可以连接；
- 公众号出口 IP 白名单没有变化。

### 常见失败提示

- `40164`：当前出口 IP 没有加入公众号白名单；
- `48001`：公众号没有对应接口权限；
- `40001`：AppSecret 或 access token 无效；
- “国际来源不足”：外网不可访问或一级来源没有合格新闻；
- “当天贴图草稿已经创建”：防重复机制生效，不要重复运行。

如果任务失败，把错误信息发给 Codex，并说：

```text
请只诊断这次绿色技术日报失败原因，不要重新发布，也不要删除现有草稿。
```

## 第一次上线建议

建议先连续运行 3 个工作日的 `draft_only`，检查来源质量、图片、标题和去重效果。确认稳定后，再由公众号负责人把 `.env` 改为 `auto_submit`。
